谁在用

同一个控制面，两种用法

个人要的是“装完就能用”，公司要的是“谁都能用，但互相看不见”。

个人

自建、自用、顺手分享

一两台 VPS，几个朋友。装完就有二维码和 hysteria2:// 链接， 谁用多少、什么时候到期，用户中心自己看。

  • 一台机器一条命令，证书、systemd、注册一次做完
  • 每个朋友一个账号，不用把节点密码发给所有人
  • 停用 / 到期 / 超额，面板点一下，连接被踢下线
  • 客户端链接带证书指纹，自签证书也不用关校验
典型规模 1–3 台节点 · 10–50 个账号
公司

多团队、多运营商，各管各的

平台方管全局，运营商管自己的节点和用户。每个运营商一个识别码、一个注册页、 一套模板——数据互相隔离，后台也互相看不见。

  • 平台 / 服务商两级后台，租户按运营商识别码隔离
  • 终端用户自助注册 /join/{code}，不用人工开号
  • 鉴权独立成服务，面板升级、重启不影响节点鉴权
  • 采集器只走面板 API：不直连库、不落第二份数据
典型规模 多运营商 · 每运营商多节点 · 用户自助增长

能力

运营里最烦的四件事，做进产品里

01

装节点：一条命令，拉的是“你的”配置

安装脚本按运营商识别码拉模板（服务商自定义优先，否则平台标准），渲染端口、混淆密码、 鉴权地址，自动生成证书并上报指纹，最后注册进面板。装完就是可用的节点，不是半成品。

  • 模板改完，节点重装即生效，不用逐台改 YAML
  • 注册失败只告警、不阻断，payload 落盘可补报
  • systemd、防火墙、trafficStats 一起配好
标准模板（面板可改）
auth:
  type: http
  http:
    url: 'https://auth.ipx.sarl/auth'
    insecure: false
trafficStats:
  listen: '0.0.0.0:8080'
  secret: per-node
02

多租户：不是加个字段，是整条链路隔离

运营商识别码同时是租户 slug、节点混淆密码、用户注册入口。后台、节点、终端用户、 配置模板都挂在它下面；平台方看全局，服务商只看见自己。

  • 每个运营商独立注册页与用户池
  • 平台可下发标准模板，服务商可覆盖自己的
  • 一套代码，两级权限，互不越界
入口各自独立
/provider/{code}          服务商后台
/join/{code}              终端用户注册
/user                     用户中心（用量 / 连接）
/admin                    平台后台（全局）
/api/collector/v1/*       采集器 API
03

流量与在线：能看，也能立刻动手

采集器轮询节点 trafficStats，按用户累计增量回传面板；在线快照、按天用量、 待踢队列都在后台。超量或停用，进队列，采集器执行踢人并回执。

  • 按天聚合，用户中心能看“每个服务器用了多少”
  • 在线 / 离线 / 最后心跳，一眼判断节点状态
  • 踢人有队列与结果回执，不是发出去就不管
采集器 → 面板
GET  /api/collector/v1/nodes
POST /api/collector/v1/ingest
GET  /api/collector/v1/kick-queue
POST /api/collector/v1/kick-result
# 采集器不连数据库，面板是唯一数据源
04

鉴权：独立进程，节点不存用户密码

Hysteria 的 HTTP 鉴权抽成单二进制服务，直接读面板库：uuid 直连、邮箱密码、 连接令牌三种凭据都认。面板重启、升级、换框架，都不影响已经连着的节点。

  • 永远 200 + ok:false，符合 Hysteria 契约
  • bcrypt 校验 + Laravel 加密令牌解密
  • 可只读运行；cache_ttl 控制停用生效速度
节点侧只认一个地址
POST https://auth.ipx.sarl/auth
{"addr":"1.2.3.4:5678","auth":"<base64(uuid)>"}

→ {"ok":true,"id":"<uuid>"}
→ {"ok":false,"msg":"账号已停用，请联系服务商"}

架构

四块，各干一件事

节点只管连和跑，面板只管数据，鉴权独立，采集器只搬数据。

快速开始

三步，从零到能连

  1. 1

    装面板

    Laravel + MySQL/SQLite，一条命令建库、迁移、起服务；平台后台建运营商，拿识别码。

  2. 2

    装节点

    在节点上粘贴命令，模板、证书、systemd、注册一次完成。

  3. 3

    给用户开号

    把 /join/{code} 发给用户，他自己注册；登录用户中心拿链接和二维码。

在节点上执行 
curl -fsSL https://hysteria.ipx.sarl/api/install.sh \
  | sudo bash -s -- --code 你的识别码
验证鉴权（应为 missing auth） 
curl -s https://auth.ipx.sarl/auth \
  -H 'Content-Type: application/json' -d '{}'
→ {"ok":false,"msg":"missing auth"}
用户注册入口 
https://hysteria.ipx.sarl/join/你的识别码

安装脚本支持 --dry-run、--register-only、--gen-cert，先在测试机跑一遍再上生产。

常见问题

上手前会问的几件事

更多细节在仓库 README，问题可以直接开 issue。

必须有自己的域名和公网 IP 吗？

节点需要公网可达（UDP）。域名不是必须的：自签证书也能用，面板会把证书指纹下发给客户端，用 pinSHA256 固定，不用关 TLS 校验。有域名就填域名，证书 SAN 会一起带上。

支持哪些系统？

安装脚本面向 Linux（systemd），amd64 / arm64 都可；采集器和鉴权服务是静态 Go 二进制，交叉编译后丢上去就能跑。面板需要 PHP 8.2+ 与 MySQL 8 / SQLite。

多运营商是怎么隔离的？

运营商识别码是租户主键：服务商后台按它分租户，终端用户挂在运营商下，注册页是 /join/{code}，节点安装时也用它拉自己的配置模板。平台方在 /admin 看全局，服务商只能看到自己的数据。

为什么把鉴权单独拆出来？

鉴权是连接链路上的热路径，面板是管理面。拆开后面板升级、重启、甚至换实现，都不会打断节点鉴权；鉴权服务也可以只读数据库、单独扩容。协议保持不变：POST /auth 永远 200，体里给 ok 与 msg。

流量数据存在哪？采集器会直连数据库吗？

只存在面板库。采集器通过面板 API 拿节点清单、回传增量、领取踢人任务，不直连数据库、不落第二份数据——少一个要备份、要对齐的地方。

能商用 / 二次开发吗？

代码在 GitHub 上，可自托管、可改。公司要多运营商、私有部署、对接自有计费或工单，按你们的流程改就行；需要人一起落地可以走仓库 issue 联系。

先在一台测试机上跑通，再决定要不要全量

面板、节点、鉴权、采集器都能单独部署，跑通了再逐台切。
